# 1.0-rc

Charmed HPC 1.0-rc is the release candidate for the `1.0` major release. It is the first Charmed HPC release to publish a tested, versioned set of charms, upstream workloads, and Terraform modules together, rather than tracking the `latest/edge` channel.

<!-- TODO: confirm release date before publishing. -->
**Release date:** TODO

:::{admonition} Release candidate
:class: warning

This is a release candidate and is **not supported for production use**. It is published so that the set of components intended for `1.0` can be validated together in representative environments.

Upgrading in place from `1.0-rc` to `1.0` is not guaranteed. Clusters deployed from this release candidate may need to be redeployed on `1.0`.
:::

## Highlights

<!-- TODO: trim to the 3-5 items the team wants to lead with. -->

- A versioned, co-tested component set for deploying Slurm-based clusters.
- Lustre parallel filesystem support through the new `lustre-server` charm.
- Active-passive high availability for the Slurm controller, including migration from an existing single-controller cluster.
- Ubuntu 26.04 LTS as the supported base for all `1.x` releases.

## New features

As the first Charmed HPC release, `1.0-rc` establishes the baseline feature set rather than adding to a previous release. The capabilities below are those validated for this release.

### Workload management

- Slurm cluster deployment and lifecycle management through the `slurmctld`, `slurmd`, `slurmdbd`, `slurmrestd`, and `sackd` charms. See {ref}`howto-deploy-deploy-slurm`.
- Compute node and partition management, including per-partition `slurmd` applications and node state control. See {ref}`howto-manage-compute-nodes`.
- Active-passive `slurmctld` high availability using Juju horizontal scaling and a shared `StateSaveLocation`, with a supported migration path from a single-controller cluster. See {ref}`explanation-high-availability` and {ref}`howto-manage-single-slurmctld-to-high-availability`.
- Generic Resource (GRES) scheduling for GPU resources. See {ref}`gres`.
- Job email notifications through integration with an external mail server. See {ref}`explanation-job-email-notifications` and {ref}`howto-integrate-email-notifications`.

### Storage

- Lustre server deployment through the `lustre-server` charm, providing MGS, MDS, and OSS components with automated LNet initialization, storage setup, and service lifecycle management. See {ref}`explanation-lustre` and {ref}`howto-deploy-deploy-lustre`.
- Shared filesystem support for NFS and CephFS through the `nfs-server-proxy` and `cephfs-server-proxy` charms. See {ref}`howto-deploy-deploy-shared-filesystem`.
- Client-side mount management through the `filesystem-client` charm, used both for user-facing shared storage and for the `slurmctld` shared `StateSaveLocation`.

### Identity and access

- LDAP-backed identity for cluster nodes using the `sssd` charm with GLAuth. See {ref}`howto-deploy-deploy-identity-provider`.
- Authentication key rotation for Slurm's SACK and JWT keys. See {ref}`explanation-key-rotation` and {ref}`howto-manage-rotate-slurm-keys`.

### Observability

- Metrics, logs, and dashboards through integration with the Canonical Observability Stack using the `opentelemetry-collector` charm. See {ref}`howto-manage-integrate-with-cos`.
- Job accounting metrics through integration with InfluxDB. See {ref}`howto-manage-integrate-with-influxdb`.
- Reference material for the shipped {ref}`reference-monitoring-grafana-dashboards`, {ref}`reference-monitoring-prometheus-metrics`, {ref}`reference-monitoring-prometheus-alerts`, and {ref}`reference-monitoring-loki-logs`.

### Running workloads

- Apptainer as a Slurm OCI runtime through the `apptainer` charm, allowing container images to be run from batch jobs. See {ref}`howto-manage-integrate-with-apptainer` and {ref}`howto-use-apptainer`.

### Hardware support

- GPU detection and driver management on compute nodes. See {ref}`explanation-gpus`.
- High-bandwidth interconnect support, including InfiniBand and cloud-specific interconnects. See {ref}`explanation-interconnects` and {ref}`reference-interconnects`.

### Deployment tooling

- Terraform modules for deploying Slurm, GLAuth, SSSD, and supporting applications, published in [`charmed-hpc-terraform`](https://github.com/canonical/charmed-hpc-terraform).
