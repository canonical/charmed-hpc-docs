# Charmed HPC 1.0-rc release notes

Release date: 2026-10-23

## Summary

Release type: Major release (release candidate)

Charmed HPC 1.0-rc is the release candidate for the `1.0` major release. It is the first Charmed HPC release to publish a tested, versioned set of artifacts, upstream projects, and third-party charm versions together, rather than tracking the `latest/edge` channel.

The primary focus of this release is establishing the `1.0` baseline on Ubuntu 26.04 LTS. 

As a release candidate, this release is **not supported for production use**. It is published so that the set of components intended for `1.0` can be validated together. Upgrading in place from `1.0-rc` to `1.0` is not guaranteed.

## What's new

As the first Charmed HPC release, `1.0-rc` establishes the baseline feature set rather than adding to a previous release. The features below are those validated for this release.

### New features

- Slurm cluster deployment and lifecycle management, through `slurmctld`, `slurmd`, `slurmdbd`, `slurmrestd`, and `sackd`. See {ref}`howto-deploy-deploy-slurm`.
- Compute node and partition management, through `slurmd`. See {ref}`howto-manage-compute-nodes`.
- Active-passive high availability for the Slurm controller, with a migration path from a single-controller cluster, through `slurmctld` and `filesystem-client`. See {ref}`explanation-high-availability` and {ref}`howto-manage-single-slurmctld-to-high-availability`.
- Lustre parallel filesystem support, through the new `lustre-server` artifact. See {ref}`explanation-lustre` and {ref}`howto-deploy-deploy-lustre`.
- Shared filesystem support for NFS and CephFS, through `nfs-server-proxy`, `cephfs-server-proxy`, and `filesystem-client`. See {ref}`howto-deploy-deploy-shared-filesystem`.
- Identity and user management with Authentik, integrated with cluster nodes through `sssd`. See {ref}`howto-deploy-deploy-identity-provider-authentik-and-sssd`.
- User and group management through the Authentik Terraform provider. See {ref}`howto-manage-users-and-groups`.
- SSH key-based authentication for cluster users, through `openssh` and `sssd`. See {ref}`howto-manage-manage-users-and-groups-set-public-ssh-keys`.
- Integration with an existing external LDAP directory, through `sssd`. See {ref}`identity-ldap-integrator-and-sssd`.
- Apptainer as a Slurm OCI runtime, through `apptainer`. See {ref}`howto-manage-integrate-with-apptainer` and {ref}`howto-use-apptainer`.
- Metrics, logs, and dashboards through integration with the Canonical Observability Stack. See {ref}`howto-manage-integrate-with-cos`.
- Job email notifications through integration with an external mail server. See {ref}`explanation-job-email-notifications` and {ref}`howto-integrate-email-notifications`.

## Requirements and compatibility

This release is supported only on the Ubuntu base and Juju versions listed below, and only with the artifact and third-party charm versions listed in these release notes. The set of versions listed here is the combination that has been tested together.

Components from different releases of the same major release (`1.x`) are designed to be forward compatible: older components can interact with newer ones, but features introduced in a newer minor release are not available to components from an older release. To use a new feature, all components that participate in it must be refreshed to the minor release that introduced it, or later.

Mismatched component versions are not officially tested. Issues encountered with newer and/or unvalidated component versions can be opened on GitHub, and community contributions to address compatibility bugs are welcome. For issues involving older and/or unvalidated component versions, the common resolution will be to update to a supported component version set.

There is no compatibility promise between components from different major releases.
